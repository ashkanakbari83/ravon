# ساخت فایل نصبی اندروید (APK)

این سند روش ساخت یک فایل APK قابل نصب از رَوون رو توضیح می‌ده — برای نصب مستقیم
روی گوشی (نه گوگل پلی). رَوون یه PWA هست، پس APK در واقع یه پوسته‌ی نازک Android
(به اسم Trusted Web Activity) هست که نسخه‌ی آنلاین رو تمام‌صفحه و بدون نوار
آدرس مرورگر باز می‌کنه؛ بعد از نصب، خودِ اپ همون‌طور که الان هست کاملاً آفلاین با
localStorage کار می‌کنه.

## چرا از GitHub Actions

ساخت APK نیاز به Android SDK مدرن و دسترسی به اینترنت (Google Maven, Gradle)
داره که تو محیط Claude در دسترس نیست. برای همین بیلد واقعی رو یه ورک‌فلوی
GitHub Actions انجام می‌ده که دسترسی کامل به اینترنت داره.

## چطور بسازیم

1. از تب **Actions** تو ریپو، ورک‌فلوی **Build Android APK** رو پیدا کن.
2. دکمه‌ی **Run workflow** رو بزن (می‌شه از شاخه‌ی دلخواه اجرا کرد).
3. چند دقیقه طول می‌کشه. بعد از اتمام، یه artifact به اسم `ravon-apk` قابل
   دانلوده که شامل این فایل‌هاست:
   - `ravon.apk` — فایل نصبی، همینو بفرست برای دوستت.
   - `ravon-release.keystore` و `keystore-credentials.txt` — کلید امضا؛ **حتماً
     نگه‌دار**. برای هر آپدیت بعدی اپ، باید با همین کلید امضا بشه، وگرنه گوشی
     آپدیت رو رد می‌کنه و دوستت باید اپ قبلی رو پاک کنه (و دیتای لوکالش رو از
     دست بده) تا نسخه‌ی جدید نصب بشه.

## نصب روی گوشی دوستت

گوشی اندروید باید اجازه‌ی «نصب از منابع ناشناس» رو برای همون اپی که فایل رو باز
می‌کنه (مثلاً مرورگر یا تلگرام) فعال کنه؛ گوشی موقع نصب خودش این گزینه رو نشون
می‌ده.

## چرا نوار آدرس مرورگر بالای اپ نیاد

برای اینکه TWA بدون نوار آدرس (کاملاً شبیه اپ واقعی) باز بشه، اندروید باید
مطمئن بشه همون کسی که دامنه (`ravon-beta.vercel.app`) رو داره، APK رو هم امضا
کرده — این کار با فایل `public/.well-known/assetlinks.json` انجام می‌شه که
بصمه‌ی (fingerprint) کلید امضا رو اعلام می‌کنه. برای همین:

1. **کلید امضا باید همیشه ثابت بمونه.** یه کلید دائمی یه بار ساخته شده و به‌صورت
   سه تا GitHub secret ذخیره شده (`ANDROID_KEYSTORE_BASE64`،
   `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_PASSWORD`). اسکریپت
   `generate-twa.cjs` اول این سکرت‌ها رو چک می‌کنه و همون کلید رو دوباره
   می‌سازه؛ فقط اگه ست نشده باشن یه کلید یک‌بارمصرف تازه می‌سازه (که دیگه با
   assetlinks.json هماهنگ نیست و نوار آدرس برمی‌گرده).
2. **فایل `assetlinks.json` باید روی آدرس واقعی (production) در دسترس باشه** —
   یعنی این تغییر باید merge بشه تا روی `ravon-beta.vercel.app/.well-known/assetlinks.json`
   دیده بشه. تا قبل از merge، APK همچنان با نوار آدرس مرورگر باز می‌شه.
3. بعد از نصب APK جدید (با همون کلید دائمی)، اندروید معمولاً تا چند دقیقه بعد
   verification رو انجام می‌ده و بعدش نوار آدرس محو می‌شه. اگه اپ قبلی رو نصب
   کرده بودی، چون کلیدش فرق داره باید اول اون رو حذف کنی.

## جزئیات فنی

- اسکریپت `scripts/android/generate-twa.cjs` با API برنامه‌نویسی‌شده‌ی
  `@bubblewrap/core` (نه CLI تعاملی‌اش) پروژه‌ی اندروید + کلید امضا رو می‌سازه؛
  مقادیر مانیفست (اسم، آیکن‌ها، رنگ‌ها، شورتکات‌ها) مستقیم از `vite.config.js`
  میان.
- `scripts/android/sign-apk.cjs` بعد از بیلد Gradle، APK رو align و امضا می‌کنه
  (قالب bubblewrap به‌صورت پیش‌فرض signingConfig نمی‌سازه).
- کلید امضا هیچ‌وقت commit نمی‌شه. نسخه‌ی دائمیش به‌صورت GitHub secret نگه
  داشته می‌شه (نه تو ریپو)؛ هر اجرای ورک‌فلو همون رو از سکرت می‌خونه و استفاده
  می‌کنه تا امضا بین بیلدها عوض نشه.
- نسخه‌ی عددی اندروید (`versionCode`) خودکار از نسخه‌ی `package.json` حساب
  می‌شه؛ در صورت نیاز با ورودی `app_version_code` موقع اجرای دستی ورک‌فلو قابل
  override هست.
